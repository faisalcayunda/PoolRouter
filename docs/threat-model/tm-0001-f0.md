# TM-0001: Threat model PoolRouter F0

**Ringkasan:** Dokumen ini memetakan ancaman pada lima alur PoolRouter F0 dengan STRIDE, dan ancaman privasi atas NIK dengan LINDDUN. Setiap ancaman dipetakan ke kontrol yang sudah diputuskan di ADR atau data contract, dan ke uji yang membuktikannya. Hasilnya: semua ancaman tingkat tinggi punya kontrol F0. Ada enam risiko sisa yang diterima untuk PoC dan ditutup di F1 atau sebelum produksi (§4). Langkah berikutnya: Quality memakai §2–§3 sebagai bahan rencana uji SHAA-175.

- **Pemilik:** Shu
- **Tanggal:** 2026-11-03
- **Status:** final rev 1 (Shu sebagai lead Engineering, R-15 SHAA-184)
- **Issue:** SHAA-184 (riset), SHAA-165 (ADR); induk SHAA-162
- **Lokasi akhir:** `docs/threat-model/tm-0001-f0.md` di repo `faisalcayunda/PoolRouter`, di commit kerangka repo pertama
- **Acuan:** ADR-0001 rev 7, ADR-0002 rev 5, ADR-0003 rev 4, ADR-0004 rev 4, data contract v0.7.4 (DC), PRD v0.4.6. Kerangka: STRIDE untuk alur, LINDDUN untuk data pribadi, NIST SP 800-228 §2 untuk identifikasi risiko API.

## 1. Lingkup, aset, dan batas kepercayaan

**Aset:** NIK dan payload (Rahasia), kredensial Dukcapil (K-07/K-08), kuota harian Dukcapil (K-22, M-02), log kepatuhan C-01 (`transaction_log`), `audit_akses`, secret client dan webhook, KEK dan kunci HMAC.

**Batas kepercayaan (B):**
- B1: aplikasi client BGN → API downstream.
- B2: PoolRouter → Dukcapil (IP privat, TLS `ca_kustom`/`pin_spki`).
- B3: PoolRouter → URL webhook client.
- B4: browser staf → nginx → admin API.
- B5: komponen PoolRouter ↔ PostgreSQL, Redis, RabbitMQ.
- B6: pipeline build dan deploy → image yang berjalan.

Di luar lingkup F0: function runner dan WASM (F2, K-31), arsip S3 dan data balikan (F1). Keduanya ditinjau saat ADR F1/F2 ditulis.

## 2. STRIDE per alur

S = spoofing, T = tampering, R = repudiation, I = information disclosure, D = denial of service, E = elevation of privilege.

| ID | Alur | STRIDE | Ancaman | Kontrol (rujukan) | Uji |
|---|---|---|---|---|---|
| TM-01 | Intake (B1) | S | Token dicuri atau dipalsukan | JWT EdDSA/ES256, `kid` → kunci → alg, `iss`/`aud`/`exp`/`nbf`, TTL 15 menit (ADR-0001 §5a.5) | DAST token: `aud` salah, `exp` lewat, `alg` lain, `kid` asing → 401 |
| TM-02 | Intake | S, D | Tebak secret di endpoint token; lockout client sah | Secret 256 bit, argon2id; throttle per client dan IP, tanpa lockout (§5a.5) | Beban token gagal → 429, client lain tetap dapat token |
| TM-03 | Intake | I | Enumerasi `request_id` milik client lain | 404 tanpa membedakan tidak ada vs milik lain (ADR-0001 §4.1) | Uji polling/pembatalan lintas client |
| TM-04 | Intake | T | Field tambahan atau kunci ganda untuk menyusupkan parameter ke Dukcapil | `deny_unknown_fields`, tolak kunci ganda, validator template (ADR-0002 D6, ADR-0001 §7) | ADR-0002 uji 9, 11 |
| TM-05 | Intake | D | Client rusak membanjiri penolakan atau kuota | Limiter penolakan per client (DC L-01…L-08), kuota efektif (§5a.1), batas ukuran body | DC U-45a…h |
| TM-06 | Dispatch dan Dukcapil (B2) | D | Melampaui kuota Dukcapil → sanksi (RR-01) | Kuota efektif + cek atomik `attempts + slot_aktif` (§5a.1), fail-closed, `pr:siap` (§5a.2), retry budget (§5a.3) | Property test Lua; chaos promosi replika; uji batas hari |
| TM-07 | Dukcapil | S | Server palsu di jaringan Dukcapil mencuri kredensial | TLS ≥ 1.2, `ca_kustom`/`pin_spki`, tanpa mode yang mematikan verifikasi; kredensial dikirim setelah handshake (ADR-0002 D5) | ADR-0002 uji 6–7 (U-42) |
| TM-08 | Dukcapil | I | Redirect mengirim ulang body berkredensial ke host lain | HTTP client tanpa redirect (ADR-0002 §2) | ADR-0002 uji 2 |
| TM-09 | Dukcapil | I | Kredensial bocor ke log lewat gema respons | Render ganda dan redaksi respons (ADR-0001 §7, DC R-04) | Fixture secret sintetis, 0 kecocokan di log |
| TM-10 | Dukcapil | R | Panggilan tanpa jejak, sehingga C-01 tidak terbukti | Log di-commit sebelum panggilan, reconciler `tidak_diketahui` (ADR-0001 §4, §5) | DC U-21, U-22a/b, DQ-05/06 |
| TM-11 | Webhook (B3) | I, E | SSRF ke metadata cloud atau jaringan internal | Allowlist saat kirim, tanpa redirect, tolak IP privat, IP di-pin (W-05…W-07) | DC U-25, U-28, U-29 |
| TM-12 | Webhook | S, T | Client menerima webhook palsu atau di-replay | Standard Webhooks: tanda tangan atas id + timestamp + body; client menolak selisih > 5 menit dan dedupe `webhook-id` (§5a.6) | Uji vektor tanda tangan dengan pustaka Standard Webhooks |
| TM-13 | Webhook | I | Secret webhook bocor | Envelope AES-256-GCM, hanya `pr_webhook` yang membaca, tampil sekali (DC §8.1a, ADR-0003 §3.6a) | DC U-23, U-24 |
| TM-14 | Admin (B4) | S | Pengambilalihan akun auditor (RR-05) | Password minimal 15, argon2id, pembatasan login, sesi `__Host-` (ADR-0003 rev 4 §3.6); PoC: allowlist IP admin, peran auditor berbatas waktu, review `audit_akses` harian (R-12 opsi b, Luca) | e2e alur 1; uji peran kedaluwarsa → 403 |
| TM-15 | Admin | T | CSRF atas aksi admin | `SameSite=Strict`, cek `Origin`/`Sec-Fetch-Site` (ADR-0003 §3.6) | Uji `Origin` asing → 403 |
| TM-16 | Admin | I | XSS mencuri data NIK di halaman auditor | CSP ketat tanpa `unsafe-inline` skrip, cookie `HttpOnly`, tanpa skrip pihak ketiga (ADR-0003 §3.9) | Listener pelanggaran CSP di e2e |
| TM-17 | Admin | I | Operator atau client owner melihat NIK utuh | Masking di view DB dan serializer; tanpa pencarian NIK; grant kolom (ADR-0001 §7.2, DC A-06) | Regex `[0-9]{16}` di respons dan DOM; uji permission denied |
| TM-18 | Admin | I | Respons NIK tersimpan di cache browser atau proxy | `Cache-Control: no-store` untuk semua respons API (§5a.8) | Cek header di semua endpoint (snapshot OpenAPI) |
| TM-19 | Admin | R | Auditor menyangkal akses atau ekspor | `audit_akses` dalam transaksi yang sama lewat `SECURITY DEFINER`, alasan wajib, checksum ekspor dihitung di DB (ADR-0003 rev 4 §3.6d) | Setiap panggilan → tepat 1 baris; checksum = SHA-256 berkas |
| TM-20 | Admin | E | Platform admin memberi dirinya peran auditor | A-02 di CLI dan API (ADR-0003 §3.6c) | Uji CLI: pelaku = penerima → ditolak |
| TM-21 | Komponen (B5) | E | Komponen yang dibobol membaca NIK atau secret di luar haknya | Role DB per komponen, grant kolom, controller tanpa SELECT NIK (ADR-0001 §7.2) | Uji permission denied per role |
| TM-22 | Komponen | I | NIK bocor ke broker, log, trace, metrik, atau log server PG | K-17, aturan §7.1, label metrik terlarang (§5a.9), `log_parameter_max_length = 0` | Pencarian NIK sintetis `00…` = 0 kecocokan |
| TM-23 | Komponen | T | Pemegang hak DB mengubah `audit_akses` (RR-09) | Append-only lewat grant, DQ-21 | DQ-21. Sisa risiko: lihat §4 |
| TM-24 | Build (B6) | T | Dependensi atau image disusupi | `cargo deny`, pin toolchain dan image, `pnpm audit`; R-14: SBOM, scan image, secret scanning, SAST (Platform & SRE) | CI gagal pada temuan kritis |
| TM-25 | Build | T | Perubahan tidak direview masuk `main` (RR-07) | K-35: review post-hoc Ridley per hash commit; R-19 ditunda Luca sebagai gerbang produksi | — (risiko sisa diterima untuk PoC) |

## 3. LINDDUN untuk NIK

| Kategori | Ancaman | Kontrol |
|---|---|---|
| Linking | Menautkan aktivitas antar-sumber lewat NIK | HMAC berkunci untuk turunan NIK (`audit_akses`, idempotensi); analitik F1 hanya HMAC (DC §10) |
| Identifying | Urutan pengiriman mengungkap daftar penerima | Anti-pola K-05: `dispatch_key` acak, jeda acak (ADR-0001 §4) |
| Non-repudiation (bagi subjek) | Log permanen membuat subjek tidak bisa menyangkal pernah divalidasi, lebih lama dari yang perlu | Purge payload P-01…P-04, retensi DC §8.4 (Q-02 menunggu owner) |
| Detecting | Keberadaan request orang tertentu terdeteksi pihak lain | 404 seragam (TM-03), pencarian NIK hanya auditor |
| Data disclosure | Kebocoran database atau backup (RR-04) | Enkripsi disk, TLS internal, backup terenkripsi (§5a.10); enkripsi tingkat aplikasi pasca-F0 (R-24) |
| Unawareness | Subjek tidak tahu datanya diproses | Di luar sistem: kewajiban pengendali BGN, gerbang PDP R-06 |
| Non-compliance | Pemrosesan tanpa DPIA atau prosedur insiden | Gerbang PoC R-06 dan R-07 (owner lewat Luca) |

## 4. Risiko sisa yang diterima untuk F0/PoC

| ID | Risiko sisa | Alasan diterima | Penutup |
|---|---|---|---|
| RS-01 | Pemegang hak DBA bisa mengubah `audit_akses` tanpa jejak kriptografis | DQ-21 mendeteksi pengurangan baris; akses DBA lingkungan BGN dibatasi BGN | R-23 (digest batch + WORM), F1 |
| RS-02 | NIK dan payload hanya dilindungi enkripsi disk | K-03; kontrol akses berlapis | R-24, F1 (dengan Klaus) |
| RS-03 | Auditor login satu faktor di PoC | Kompensasi R-12 opsi b (Luca) | MFA F1 (K-37), wajib sebelum produksi |
| RS-04 | Pelaku CLI pengguna/peran dinyatakan, bukan dibuktikan | Akses `exec` terbatas; semua tercatat (ADR-0003 §3.6c) | UI pengguna + MFA F1 |
| RS-05 | Review kode post-hoc (K-35) | Kecepatan PoC; keputusan owner | R-19, gerbang produksi |
| RS-06 | Tanpa circuit breaker penuh | Retry budget dan batas percobaan membatasi dampak (§5a.3) | R-26, F1 |
